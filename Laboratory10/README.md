Отчёт по лабораторной работе 10 ( все результаты находятся в файле Results) 

1. Замер времени (только Python)
При увеличении n_iter время растёт линейно.
2. Оптимизация с помощью потоков
Использован ThreadPoolExecutor.
Результат - время выполнения почти не отличается от однопоточной версии, потому что 
GIL блокирует параллелизм в CPU-bound задаче.
3. Оптимизация с помощью процессов
Использован ProcessPoolExecutor.
Результат - время выше, чем у однопоточной версии, потому что 
накладные расходы на запуск процессов и передачу данных перевешивают выгоду при малом объёме вычислений.
Процессы эффективны только при больших n_iter.
4. Оптимизация с помощью Cython
Реализована версия integrate_cy на Cython с nogil.
Результат - ускорение в примерно 30 раз.
Cython существенно ускоряет CPU-bound код.
5. Отпускание GIL (noGIL)
В Cython-коде использован блок with nogil.
При запуске с 4 потоками - время увеличилось, ускорение примерно в 0.6x, потому что 
при малом объёме вычислений накладные расходы на создание потоков превышают выгоду от параллелизма.
nogil быстрее только при достаточно больших задачах.
6. Применение примитивов синхронизации
Каждый поток или процесс работает с независимым подотрезком, общее состояние обновляется только
после завершения всех вычислений.
Вывод. 
Для небольших задач лучший результат даёт однопоточный Cython.
Потоки в чистом Python неэффективны из-за GIL.
Процессы и многопоточность в Cython оправданы только при больших объёмах вычислений.
