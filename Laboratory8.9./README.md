Описание реализации:

Как реализованы модели и их свойства (геттеры/сеттеры)?

Каждая модель предметной области (Author, App, User, Currency, UserCurrency) реализована как отдельный класс в соответствующем файле внутри папки models/.
Сеттеры проверяют тип значения (например, id должен быть целым числом, name — строкой). При нарушении условий выбрасывается исключение ValueError с понятным сообщением.
Геттеры просто возвращают значение приватного атрибута без дополнительной логики.
Такой подход обеспечивает инкапсуляцию, целостность данных и защиту от некорректного использования модели извне.

Как реализованы маршруты и обработка запросов?

Поддерживается пять основных маршрутов:
Главная страница с информацией о приложении.
author - данные об авторе.
users - список всех пользователей.
user -  профиль конкретного пользователя. 
currencies - список всех валют с актуальными курсами.
Для каждого маршрута:
Формируется соответствующий контекст данных (например, список пользователей или объект автора).
Вызывается функция рендеринга шаблона с передачей этого контекста.
При ошибках (например, передан несуществующий id) сервер отвечает статусом 404. 

Как используется шаблонизатор Jinja2? (с объяснением инициализации Environment)

Для генерации HTML-страниц используется библиотека Jinja2.
Объект Environment инициализируется один раз при запуске приложения:
В качестве загрузчика используется FileSystemLoader("templates"), что указывает Jinja2 искать шаблоны в папке templates. 
Инициализация выполняется единожды, чтобы:
Избежать повторной загрузки шаблонов при каждом запросе.Использовать встроенный кэш шаблонов Jinja2 для повышения производительности.
При обработке каждого маршрута:
Вызывается метод get_template("имя_файла.html") у объекта env. Шаблон рендерится с переданным контекстом данных. Результат (строка HTML) кодируется в UTF-8 и отправляется в HTTP-ответ.

Как интегрирована функция get_currencies для получения актуальных курсов?

Функция get_currencies размещена в модуле utils/currencies_api.py и отвечает за получение и обработку данных о курсах валют.
Источник данных: официальный XML-фид Центрального банка РФ.
Этапы работы функции:
    1. Выполняется HTTP-запрос к XML-фиду с помощью  библиотеки urllib.
    2. Ответ парсится.
    3. Для каждой валюты (<Valute>) извлекаются: ID, NumCode, CharCode, Nominal, Name, Value.
    4. Значение курса (Value) преобразуется: запятая заменяется на точку, затем строка приводится к float.
    5. На основе полученных данных создаются экземпляры класса Currency.
    6. Функция возвращает список объектов Currency.
Обработка ошибок:
При сетевых сбоях, недоступности ресурса или повреждённом  выбрасываются исключения.
Эти исключения перехватываются в контроллере, и пользователю отображается понятное сообщение об ошибке. 
Использование в приложении:
При запросе /currencies функция вызывается напрямую, и все валюты отображаются в таблице.
При запросе /user?id=... функция также вызывается, но из всего списка выбираются только те валюты, на которые подписан пользователь (через связь UserCurrency).
